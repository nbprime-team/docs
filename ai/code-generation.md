## 硬性约束
**任何情况下，遵循以下约束；以下约束具有最高优先级，与其他指令冲突是以以下约束为准。**
1. 生成内容前**永远**阅读 Nbprime 项目仓库，了解实现相关文档和最新变化，及时更新知识库。
2. **永远**优先使用 NbPrime 仓库 `src/lib` 或 `include` 中封装好的 API（包括项目移植的受限 libc 子集）。调用任何系统级 API 前，务必对照 HP Prime 官方 ABI/后门文档，**严禁**臆造函数。
3. **永远**先确认运行时环境，避免绕过标准 C 库访问 ABI，**严禁**访问未知的 ABI 地址；**永远**处理所有错误；**永远不要**超过平台内存限制（G1 为 32MB）或自行尝试超频（G1 主频 400MHz，足够应对日常任务）。
4. **必须**在所有文件醒目位置添加“**某某 AI 生成 / 辅助创作（未人工审查）**”字样。

## 代码规范
- 语言标准：C89/C90 为基准，谨慎使用 C99 特性，**避免 C11 及以后的所有特性**。C 标准的可选特性默认不支持。
- 编码风格：以 Nbprime 仓库编码风格为基准，参考 Linux 规范。具体包括：
  - 缩进使用 4 个空格，不使用 Tab
  - 大括号采用 K&R 风格（左括号不换行）
  - 函数命名使用 `snake_case`，宏命名使用 `UPPER_CASE`
  - 行宽不超过 80 字符
- 注释要求：关键函数和复杂逻辑需添加注释
- 错误处理：需考虑边界条件和异常情况

## 文档规范
- 文档语言：任何情况下提供中文，若用户要求可同时提供英文，**暂不提供其他语言**。
- 文档风格：以 Nbprime 仓库编码风格为基准，参考 Linux 规范。

## 测试规范
- **模拟单元测试**：在 PC 端交叉编译及静态分析，找出所有可能错误。
- **集成测试**，编译成二进制文件，等待用户反馈实体机运行结果。
- **实机环境调试**：编译二进制文件，包含详细的输出、日志，便于定位和修正错误。
- **工作流程**：所有文件/模块在完成后模拟单元测试，检查正确性；实现单个功能后集成测试，若有异常，及时创建实机环境调试文件并接受用户反馈输出。循环直到需求实现。
> 若是云端 AI 或无工具调用权限，需在生成的代码中嵌入充足的静态断言和边界检查，并输出完整的 Makefile 编译命令。开发者本地运行。
